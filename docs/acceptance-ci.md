# PR 验收检查

工作流执行 PR 的准确 head 提交，使用 GitHub 托管临时执行器，不使用个人电脑作为公共 PR 的自托管执行器。权限仅 `contents: read`，不注入模型、邮箱或生产凭据。

| 检查 | 执行方式 | 证据 |
| --- | --- | --- |
| Python 回归 | 安装项目 `[dev,rag]` 后运行仓库全部 pytest | JUnit、覆盖率、实际依赖版本 |
| 前端构建 | `npm ci` 与 `npm run build` | 构建日志、锁文件哈希 |
| Python 静态安全 | Bandit 1.8.6 扫描 src | JSON 原始结果、环境版本 |

`acceptance/scoped` 只有三个 job 都成功才成功；失败、取消、跳过不放行。未降低规则严重级别、未新增忽略列表。已有静态规则命中需要逐项复核，不代表已经证实可利用漏洞。

每份工件含实际提交 SHA 与 SHA-256 清单，保存 30 天。Python 当前没有依赖锁文件，因此保留实际安装版本，但不宣称跨时间完全可复现。没有模型密钥的现有测试按原测试定义跳过，JUnit 保留跳过数量；这不是完整验收。

工作流提供检查结果。仓库管理员将 `acceptance/scoped` 配为目标分支必需检查后，才能强制阻止未通过的 PR 合并；仅添加 YAML 不会自动启用分支保护。若要接入外部验收 Agent 的完整结果，应使用另一个明确标记 full 的检查，并绑定同一提交和已核验的完整证据。

此变更仅增加 CI 和说明，不改变应用源码或现有测试来获取通过结果。
